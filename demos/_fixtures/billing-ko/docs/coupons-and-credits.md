# 쿠폰과 크레딧

`src/coupons.js`는 금액에서 할인액을 빼는 산수만 한다. 어떤 쿠폰을 누구에게 언제 쓸 수 있는지,
크레딧과 쿠폰이 겹치면 무엇을 먼저 쓰는지, 세금과의 관계는 여기 정책이 정한다.

## 1. 쿠폰의 종류와 발급 주체

| 종류 | 코드 접두 | 발급 주체 | 비용 부담 | 비고 |
|---|---|---|---|---|
| 마케팅 쿠폰 | 없음 (예: `LAUNCH50`) | 마케팅팀 | Workhub | 캠페인 단위. 만료일 필수 |
| 파트너 쿠폰 | `P-` (예: `P-ACME-20`) | 파트너사 | 파트너와 분담 | 월별 정산. 다른 쿠폰과 중복 불가 |
| 세일즈 쿠폰 | `S-` | 영업팀 | Workhub | 건별 발급. 영업 리드의 승인 기록 필요 |

- 파트너 쿠폰은 파트너 계약에 따라 할인액의 절반을 파트너가 부담한다. 매달 5일에 파트너별 사용 내역을 정산 리포트로 보낸다.
  파트너 쿠폰은 **다른 어떤 쿠폰이나 크레딧과도 겹쳐 쓸 수 없다**. 겹치면 파트너 부담분을 계산할 수 없기 때문이다.
- 마케팅 쿠폰과 세일즈 쿠폰은 한 청구서에 하나만 쓴다. 쿠폰 두 장을 겹치는 기능은 없고, 만들 계획도 없다.

## 2. 적용 순서와 부가세

한 청구서 안에서 금액은 다음 순서로 줄어든다. 각 단계에서 원 미만은 버린다.

1. 공급가액(플랜 요금 또는 일할 계산 결과)
2. 크레딧 차감 (있으면)
3. 쿠폰 적용 (있으면)
4. 부가세 계산 (3번 결과의 10%)

- **쿠폰과 크레딧은 공급가액에만 적용한다.** 세액에는 적용하지 않는다. 세법상 할인은 공급가액의 감액이고, 세액은
  감액된 공급가액에서 다시 계산된다. 세액을 직접 깎으면 세금계산서가 틀린다.
- 크레딧을 쿠폰보다 먼저 쓰는 이유: 크레딧은 장애 보상이라 소멸 기한이 있고, 쿠폰은 고객이 고른 것이라
  다음 달에도 쓸 수 있는 경우가 많다. 2023년 장애 보상 때 크레딧이 소멸된 고객 민원이 있어 순서를 확정했다.

## 3. 크레딧

- 크레딧은 **장애 보상**으로만 발급한다. 마케팅 목적의 크레딧은 없다. 2023년 6월 장애(INC-2023-06) 때
  영향받은 계정 1,850곳에 월 요금의 20%를 크레딧으로 줬다.
- 크레딧은 현금으로 환불하지 않는다. 다음 청구서부터 자동 차감된다. 소멸 기한은 발급일로부터 6개월이다.
- 다운그레이드해도 크레딧은 유지된다. 해지하면 소멸한다.
- 크레딧은 계정 단위(`account.credits`, 원 단위 정수)다. 한 청구서에서 다 쓰지 못하면 잔액이 다음 청구서로 넘어간다.

## 4. 할인 한도

- 퍼센트 쿠폰은 **최대 50%**다. 50%를 넘는 할인은 2022년 이사회에서 "매출 인식 왜곡"을 이유로 금지했다.
  시스템은 50% 초과 퍼센트 쿠폰의 생성과 적용을 모두 거부해야 한다.
- 정액 쿠폰이 공급가액을 넘으면 공급가액을 0원으로 만들고 **잔액은 소멸**한다. 이월하지 않는다.
  잔액 이월은 회계상 부채로 잡혀야 해서 회계팀이 거부했다.
- 0원 청구서도 발행한다. 세금계산서도 0원으로 나간다. 청구서를 건너뛰면 번호 연속성이 깨진다.

## 5. 레거시 플랜과 쿠폰

- 레거시 플랜(`L-`)에는 마케팅 쿠폰과 파트너 쿠폰을 적용할 수 없다. 계약 가격이 고정돼 있어 할인이 계약 금액과
  어긋나고, 회계에서 계약 매출과 청구 매출이 달라진다.
- 세일즈 쿠폰은 레거시에도 가능하다. 서면 계약을 수정하는 절차(부속 합의서)를 거친 뒤 영업팀이 발급한다.

## 6. 쿠폰 코드와 사용 조건

- 코드는 대문자 영숫자와 하이픈만 쓴다. 최대 32자. 대소문자를 구분하지 않고 비교한다.
- 한 계정은 같은 쿠폰을 한 번만 쓴다. 청구서가 취소되면(수정세금계산서 발행) 쿠폰 사용 이력도 되돌린다.
- 만료일은 KST 기준 그날 23:59:59까지 유효하다. 청구 배치가 09:00이므로 만료일 당일 청구에는 쓸 수 있다.
- 쿠폰은 업그레이드 일할 청구서에도 적용할 수 있다. 다만 파트너 쿠폰은 정기 청구서에만 적용한다.

## 7. 남용 사례와 대응

- 2024년 4월, `LAUNCH50`을 같은 사업자등록번호로 계정 여러 개를 만들어 반복 사용한 사례가 있었다.
  이후 쿠폰 사용 이력을 계정이 아니라 **사업자등록번호** 기준으로 본다.
- 파트너 쿠폰 코드가 커뮤니티에 유출된 적이 있다. 파트너 쿠폰은 파트너가 등록한 고객 목록의 계정에만 적용한다.

## 8. 쿠폰 데이터 필드

| 필드 | 뜻 | 비고 |
|---|---|---|
| `code` | 쿠폰 코드 | 대문자 영숫자, 하이픈. 최대 32자 |
| `type` | `percent` 또는 `fixed` | 다른 유형은 없다 |
| `value` | 퍼센트(1~50) 또는 원 단위 정액 | percent는 50 초과 불가 |
| `expiresOn` | 만료일(KST 달력 날짜) | 필수 |
| `issuer` | `marketing`, `partner`, `sales` | 코드 접두와 일치해야 한다 |
| `partnerId` | 파트너 쿠폰의 파트너 | 파트너 쿠폰만 값이 있다 |
| `maxUses` | 전체 사용 횟수 한도 | 마케팅 쿠폰만. `null`이면 무제한 |

## 9. 적용 예시

정기 청구서, Team 플랜 99,000원, 크레딧 잔액 30,000원, 마케팅 쿠폰 `SPRING10`(10%).

| 단계 | 계산 | 결과 |
|---|---|---|
| 공급가액 | 99,000 | 99,000 |
| 크레딧 | 99,000 − 30,000 | 69,000 (크레딧 잔액 0) |
| 쿠폰 10% | 69,000 − floor(6,900) | 62,100 |
| 부가세 | floor(62,100 × 0.1) | 6,210 |
| 합계 | | 68,310 |

같은 상황에서 크레딧 잔액이 120,000원이면 공급가액은 0원이 되고 크레딧 잔액 21,000원이 다음 달로 넘어간다. 쿠폰은 0원에 적용할 수 없으므로
사용 이력을 남기지 않고 다음 청구서에 다시 쓸 수 있다.

파트너 쿠폰 `P-ACME-20`이 있는 계정에 크레딧 30,000원이 있으면, 파트너 쿠폰은 크레딧과 겹칠 수 없으므로 **크레딧을 먼저 쓰고 쿠폰은 건너뛴다.**
크레딧이 소멸 기한이 있어서다. 이 경우 고객에게 "이번 달은 크레딧이 적용됐고 파트너 쿠폰은 다음 달에 적용된다"고 청구서 메모에 적는다.

## 10. 파트너 정산 리포트

- 매달 5일 09:00에 전월 파트너 쿠폰 사용 내역을 파트너별 CSV로 만든다. 컬럼: 계정 ID, 청구서 번호, 할인 전 공급가액, 할인액, 파트너 부담분.
- 파트너 부담분은 할인액의 50%를 절사한 값이다. 파트너 계약마다 비율이 다를 수 있으나 지금은 전부 50%다.
- 수정세금계산서로 취소된 청구서의 쿠폰 사용은 리포트에서 음수 줄로 나간다.

## 11. 구현할 때 자주 틀리는 것

- 쿠폰을 부가세 포함 금액에 적용하는 것. 공급가액에만 적용한다.
- 크레딧보다 쿠폰을 먼저 적용하는 것. 순서는 크레딧 → 쿠폰 → 부가세다.
- 정액 쿠폰 잔액을 이월하는 것. 잔액은 소멸한다.
- 레거시 플랜에 마케팅 쿠폰을 허용하는 것.
- 파트너 쿠폰을 다른 할인과 겹치는 것.
- 50% 초과 퍼센트 쿠폰을 "값이 그렇게 들어왔으니" 적용하는 것. 거부해야 한다.
